## 해밍 가중치(Hamming Weight)

---

해밍 가중치(Hamming Weight) : 비트열에서 1의 개수를 말한다.

| 비트열 | 10110110 | 10001010 |
| --- | --- | --- |
| 해밍 가중치 | 5 | 3 |

## 해밍 가중치와 전력 소비의 관계

---

MCU(마이크로컨트롤러) 에서는 비트가 1로 설정된 경우가 0보다 많은 전력을 소비한다고 한다. 즉 해밍 가중치에 따라 전력 소모량이 다르다는 애기이다.

정확한 이유를  찾아볼려고 했는데 어려워 보여서 일단 멈췄다.

이거는 언젠가 알아보고, 실제로 해밍 가중치가 전력을 소비에 영향을 주는지 테스트를 해보자.

아래 코드는 AES-128 암호화가 구현된 펌웨어에 랜덤한 평문을 simpleserial 통신을 통해 전달하는데

이 평문들에 대해 암호화된 결과 값이 나올때 까지의 전력 트레이스를 캡쳐하며 이를 2000번 반복하여

총 2000개의 전력 트레이스를 캡쳐한다.

```python
from tqdm.notebook import trange
import numpy as np
import time

ktp = cw.ktp.Basic()
trace_array = []
textin_array = []

key, text = ktp.next()

target.set_key(key)

N = 2000
for i in trange(N, desc='Capturing traces'):
    scope.arm()

    target.simpleserial_write('p', text)

    ret = scope.capture()
    if ret:
        print("Target timed out!")
        continue

    response = target.simpleserial_read('r', 16)

    trace_array.append(scope.get_last_trace())
    textin_array.append(text)

    key, text = ktp.next()
```

```python
    return sbox[inputdata ^ key]
```

해밍 가중치를  반환하는 함수

```python
def calc_hamming_weight(n):
    return bin(n).count("1")
```

전 글을 보면 aes_internal 함수의 결과의 첫 비트를 1이냐 0이냐의 차이로 aes의 키를 구했었다.

이번에는 이걸 해밍 가중치와 연관짓기 위해서 첫 비트가 아닌 첫 바이트의 해밍 가중치를 계산해서 해밍 가중치가 0 ~ 8 로 갈 때, 실제 선형적인 그래프가 나오는지 확인해볼 것이다.

전력을 측정해서 비교할 부분은 AES 암호화에서 처음 부분의 SubBytes(AddRoundKey(input, key)) 이다. 이를 첫 sbox 출력 또는 연산이라 줄여서 부르겠다.

그전에 실제 첫 sbox의 출력에서 나오는 전력 트레이스가 어딘지를 알아야한다.

일단 처음 연산을 하는 부분이니 대략적으로 범위를 0~2000까지 잡는다.

아래의 코드는 평문의 첫번째 바이트를 aes_internal 함수에 넣어 나온 반환 값의 해밍 가중치를 계산해서,

수집한 전력 트레이스를 해밍 가중치별로 분류하여 저장하고, 각 해밍 가중치 그룹별로 평균을 구해서

전체 전력 트레이스와의 차이를 그래프로 그리는 코드이다.

```python
import numpy as np
from bokeh.plotting import figure, show
from bokeh.io import output_notebook, reset_output
from bokeh.palettes import brewer

output_notebook()
reset_output()  
p = figure()

# 전체 전력 트레이스의 평균 계산
avg_trace = np.asarray(trace_array).mean(axis=0)  

# 첫 sbox 연산이 있을 것으로 추정되는 범위 0 ~ 2000
plot_start = 0
plot_end = 2000

bnum = 0 # 첫번째 바이트
hw_averages = [[] for _ in range(9)] # 해밍 가중치 별 트레이스의 평균을 저장할 변수

for tnum in range(len(trace_array)):
    # 평문의 첫 바이트를 aes__internal에 넣고 나온 값을 해밍 가중치로 계산
    hw_of_byte = HW[aes_internal(textin_array[tnum][bnum], key[bnum])]
    # 해밍 가중치별로 구분하여 리스트에 저장
    hw_averages[hw_of_byte].append(trace_array[tnum])

# 각 해밍 가중치 그룹들의 평균을 계산
for i in range(9):
    hw_averages[i] = np.asarray(hw_averages[i]).mean(axis=0)

xrange = list(range(len(trace_array[0]))[plot_start:plot_end])
color_mapper = brewer['PRGn'][9]

# 해밍 가중치별로 전체 전력트레이스의 평균의 차이를 그래프로 출력
for hw in range(9):  
    p.line(xrange, (hw_averages[hw]-avg_trace)[plot_start:plot_end], line_color=color_mapper[hw])

show(p)
```

위 전력 트레이스는 각각의 해밍 가중치 별로, 전체 전력 트레이스의 평균을 뺀 그래프이다.

실제 첫 sbox 연산이 이루어지는 부분은

해밍 가중치가 가장 낮은 (해밍 가중치가 0인) 전력 트레이스 평균에다 전체 전력 트레이스의 평균을 뺀 값에서 가장 큰 부분일 것이다.

왜나하면, 첫 sbox 출력의 해밍 가중치로 캡쳐를 분류했기 때문에, 캡쳐한 것들에서 차이가 크게 날 부분은 sbox 출력 부분이기 때문이다.

전체 전력 트레이스의 평균 : 첫 sbox 출력 부분이 평균 값

해밍 가중치가 가장 낮은 (해밍 가중치가 0인) 전력 트레이스 평균 : 첫 sbox 출력 부분이 가장 낮음

|(해밍 가중치가 가장 낮은 전력 트레이스 평균)  - (전체 전력 트레이스의 평균)| <= 이 값이 가장 큰 부분이 첫 sbox출력 부분

```python
# sbox 출력 위치
sbox_loc = np.argmax(abs(hw_averages[0]-avg_trace))
```

이제 sbox의 위치를 알았으므로 각 해밍 가중치 그룹별로 평균을 구하고, 구한 위치에 해당하는 값을 0 ~ 8 순으로 그래프로 나타내보자.

코드는 아래와 같다.

```python
output_notebook()
hw_averages = np.array(hw_averages)
p = figure(title="HW vs Voltage Measurement")
```
